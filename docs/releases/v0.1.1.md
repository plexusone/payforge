# v0.1.1

**Release Date:** 2026-11-11

A patch release that settles which hosts count as the developer's own
machine. With a test-mode key, checkout and the portal may return to names
under `localhost` as well as `localhost` itself, so a local setup that serves
its apps on names such as `app.localhost` and `auth.localhost` needs no
`AllowedURLHosts` entry for them. A live key refuses all of them.

## Highlights

- **Names under `localhost` are loopback hosts.** RFC 6761 reserves them for
  the loopback interface. With a test-mode key they are accepted over `http`
  too, without being listed; with a live key they are refused, both in
  `AllowedURLHosts` when the client is made and in a URL.

## Fixed

- **A trailing dot doesn't change a host.** `app.localhost.` is the same host
  as `app.localhost`, in `AllowedURLHosts` and in URLs. Before, a live
  configuration could list a loopback name with a trailing dot and redirect to
  it.
- **Every loopback address is loopback.** All of `127.0.0.0/8` and `::1`
  count, not only `127.0.0.1` and `::1`, so a live key also refuses
  `127.0.0.2` and the like.

See [checkout](../guide/checkout.md#urls) for the full URL rules.

## Dependencies

- `systemspec-pricingpackaging` v0.2.0, which adds internal plans for a
  product's own accounts. Checkout refuses them, as it refuses every plan that
  is not self-serve, and they have no prices to sync.
- `stripe-go` v87.1.0 and `oscompat` v0.13.0.

## Installation

```bash
go get github.com/plexusone/payforge@v0.1.1
```

Requires Go 1.26.

## Upgrade notes

No API changes. A test-mode client now accepts URLs on names under
`localhost` that it refused before; a live client refuses loopback hosts it
could be configured with before, which only a misconfigured live setup would
notice.
